# Мини-склад

Сайт учёта склада для BMS Smart Home: товары, приход, выдача на объекты, отмена операций, история.
Работает в браузере на компьютере и на телефоне. Размещается на **Netlify**.

**Сайт:** https://mini-sklad.netlify.app

## Как устроено

- `public/` — сам сайт (HTML/CSS/JS без фреймворков), языки RU / UZ.
- `netlify/functions/api.mjs` — серверная функция Netlify: обслуживает все адреса `/api/*`.
- `src/sklad.mjs` — вся бизнес-логика. **Права проверяются на сервере**: кладовщику цены не отправляются вообще.
- Данные хранятся в **Netlify Blobs** — встроенном хранилище Netlify, отдельная база не нужна.
  Каждая запись условная (по версии документа), поэтому одновременные операции не уводят остаток в минус.
- `tests/` — автотесты.

## Публикация на Netlify

**Способ 1 — из GitHub (рекомендуется).** Netlify → *Add new site* → *Import an existing project* → GitHub →
репозиторий `mini-sklad` → *Deploy*. Настройки сборки подтянутся из `netlify.toml` сами.
После каждого `git push` сайт обновляется автоматически.

**Способ 2 — из командной строки** (нужен Node.js 18+):
```bash
npm install
npx netlify-cli login
npx netlify-cli deploy --prod
```

Netlify Blobs включается автоматически, ничего настраивать не нужно.

## Запуск на своём компьютере

Нужен Node.js 18+ (https://nodejs.org).
```bash
npm install
npx netlify-cli dev
```
Откройте адрес, который покажет команда (обычно http://localhost:8888).

## Пользователи

| Роль         | Логин      | Что может |
|--------------|------------|-----------|
| Руководитель | `director` | Всё: товары, приход, выдача, отмена, история; видит цены |
| Кладовщик    | `sklad`    | Приход и выдача; цен не видит нигде |
| Менеджер     | `manager`  | Только смотрит остатки и историю; видит цены |

**Пароли на сайте** задаются в Netlify → *Project configuration → Environment variables* (с отметкой *Secret*)
и в коде не хранятся:

| Переменная | Значение |
|---|---|
| `SKLAD_PASSWORD_DIRECTOR` | пароль руководителя |
| `SKLAD_PASSWORD_SKLAD` | пароль кладовщика |
| `SKLAD_PASSWORD_MANAGER` | пароль менеджера |
| `SKLAD_REQUIRE_ENV_PASSWORDS` | `1` — стандартные пароли перестают работать |

После изменения переменных: *Deploys → Trigger deploy*. Пароли для проверки передаются отдельно, не через репозиторий.

При локальном запуске без этих переменных работают тестовые пароли `director123`, `sklad123`, `manager123`.

## Безопасность

- **Права проверяются только на сервере.** Интерфейс ничего не решает: кладовщику сервер не отдаёт цены, а запрещённое действие получает отказ 403.
- **Защита от перебора паролей.** После 5 неудачных попыток логин блокируется на 15 минут, с одного IP — не больше 20 попыток за 15 минут.
- **Пароли.** Хранятся вне кода (переменные Netlify), сравниваются за постоянное время. Хеш считается и для несуществующих логинов, поэтому по времени ответа логины не угадать.
- **Сессии.** Токен случайный (256 бит), в базе лежит только его хеш. Cookie `__Host-sid`: HttpOnly, Secure, SameSite=Strict. Срок жизни — 12 часов, выход сразу удаляет сессию.
- **CSRF.** Изменять данные можно только JSON-запросом с этого же сайта (проверка Origin и SameSite=Strict).
- **XSS.** Весь пользовательский текст экранируется. Content-Security-Policy разрешает скрипты только с этого сайта.
- **Заголовки.** HSTS, `X-Frame-Options: DENY` (сайт нельзя встроить в чужую страницу), `nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`.
- **Ввод.** Все поля проверяются на сервере, запрос больше 20 КБ отклоняется, внутренние ошибки наружу не показываются.
- **Одновременные запросы.** Запись условная (по версии данных), поэтому гонки не уводят остаток в минус.
- **Зависимости.** Одна библиотека (`@netlify/blobs`), `npm audit` — 0 уязвимостей.

## Автотесты

```bash
npm test
```

Тесты проверяют: пример из раздела 10 ТЗ целиком, правило «не в минус» (в том числе при одновременных запросах),
права ролей при запросах в обход экрана, отмену, двойное нажатие, деньги без ошибок округления, сообщения на узбекском,
а также защиту: блокировку перебора паролей, пароли из переменных окружения, срок и хеширование сессий, CSRF, лимит размера запроса.
